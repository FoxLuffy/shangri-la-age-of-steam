# Playtest Evaluation — 2026-07-26 (prod)

Session: demo account on production (`saos-api.atelierbungle.org`), character **Cogsworth
Vale** (Alchemist / Guild Apprentice). 9 adaptive turns + browser screenshots of the live
UI. Full transcript in the harness log; screenshots captured for landing/login/lobby/
session-select/game/map/market.

## TL;DR
Narration is genuinely good — atmospheric, on-theme, and continuous. But **no player action
in chat ever changed mechanical state**: across all 9 turns `state_updates` was `{}`. Buying
gears, earning a reward, completing a task, fighting, and hacking a lock were all pure
fiction — coins stayed 100, inventory unchanged, no quests, no combat, no minigame. The
mechanical systems (Market, Bounties, Workbench, Combat) *do* work via their dedicated UIs;
the **narrative engine is disconnected from them.**

## Findings (ranked)

### F1 — CRITICAL: chat actions never produce state updates
Every `/chat` turn returned `state_updates: {}` and `events: []`. Server truth after 9
turns: `brass_coins` still 100, `/inventory` still just the 2 starting items, `/quests`
empty, `is_combat_active` false, no minigame.
- The model outputs a `[Narration]` block only; it never emits the `[StateUpdates]` /
  `[Events]` sections the parser (`engine.parse_vllm_response`) expects, so nothing is
  applied. The parser itself is fine — the model isn't producing structured output.
- Impact: the entire sim (economy, inventory, quests, combat, minigames) is unreachable
  from natural play. This is the root of the "inaccurate narrative" feeling (CR6) and why
  "start minigame" rarely has anything to start (CR3's trigger never fires — even an
  explicit "hack the lock" produced no `minigame_trigger`).
- Directions: (a) strengthen `narrative_prompt.j2` to REQUIRE a `[StateUpdates]` JSON block
  every turn (explicit schema + few-shot examples + "emit `[StateUpdates] {}` if nothing
  changed"); (b) validate/retry when the block is missing; (c) consider tool/function-call
  style structured output or a stronger model; (d) optionally map common verbs
  (buy/earn/take/attack) to deltas as a safety net.

### F2 — HIGH: `[Narration]` tag leaks into the streamed text
The streamed narration still contained the literal `[Narration]` header (the non-stream
parse strips it, the streaming path doesn't fully). Players can see raw section tags.

### F3 — CR6 nuance: continuity is actually good; the pain is state desync
Short-term memory held well — at turn 8 the narrator correctly recalled the valve task from
turn 1 across travel. So CR6 ("no context") is less about the context window and more about
narration asserting outcomes the character sheet never reflects → reads as "inaccurate."
Fixing F1 largely resolves CR6 as experienced.

### F4 — CR8: narrator describes beautifully but rarely leads
Rich sensory prose, but little forward push — no explicit hooks, stakes, or choices. Matches
the "steer the narrative more, don't just describe" request. Prompt-tunable.

### F5 — CR7 NOT reproduced (duplicate locations)
9 turns incl. travel + exploration kept exactly 5 clean locations, no duplicates.
Exploration is narrative-only (doesn't persist new locations). Needs a targeted repro —
hypotheses: the model emitting `location_name` state-updates with slightly varied names
(once F1 is fixed and updates flow), mod/import paths, or re-seeding. Flag for a focused
session once F1 lands.

### F6 — MINOR: SSE splits multibyte chars
Occasional mojibake (e.g. `They�re`) when a stream chunk boundary splits a UTF-8 sequence.
Streaming/encoding robustness.

## Positives
- Narration quality: atmospheric, consistent voice, good use of the global event (festival)
  and origin (Apprentice Badge, Guild). Continuity across turns + travel.
- UI is polished and functional: Dossier (stats/wealth/inventory), mood selector,
  Exploration toggle, and working Market / Bounties / Workbench / Map / Journal panels.
- CR4 fix visible: `active_npcs` update correctly per location on travel.
- Latency ~13–14 s per turn (LLM-bound; streaming softens it).

## Proposed next steps (for discussion)
1. **NEW — top priority:** narrative→state bridge (F1). Make the model reliably emit
   `[StateUpdates]`; this is the single highest-leverage fix and largely resolves CR6 and
   CR3-in-practice.
2. F2: strip `[Narration]` in the streaming path (quick).
3. CR8 (F4): prompt guidance to lead, not just describe.
4. CR7 (F5): dedicated repro session after F1.
5. F6: UTF-8-safe SSE chunking (quick).
6. CR9 (varied start), CR10 (main-quest arc) — feature work, schedule after the core
   narrative→state fix.
