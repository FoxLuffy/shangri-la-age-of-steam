## Playtest evidence (22 turns + probes)

**Positives**
- Narrative quality high: atmospheric, in-tone, coherent across all 22 turns. Latency healthy (6–11 s/turn).
- State extraction reliable: T13 buy → coins 100→70 and **Pressure Gauge** added; T15 crafting produced **Pressure Vent-Cap**; main quest renders 1/4 in the Dossier.
- **Earshot works** (post-#179/#180): explicitly naming *Lady Eleanor Vane* set her `in_earshot=True` and all others False (focus-shift correct). Report #1's "assumes talking to him" is resolved — it was filed before the earshot deploy.
- **Travel works backend-side**: sending a new `current_location_id` moved 4→1 and swapped the location's NPCs correctly.

**Confirmed problems**
- **Combat spawn leak (NEW, P0):** a freshly created character spawned with `is_combat_active=True`; combat stayed stuck for 7 turns (T01–T07) despite non-combat actions, clearing only at T08. Global `WorldState.is_combat_active` leaks into new characters.
- **Junk enemy NPC (NEW, P0 — regression from #179):** the model emitted `combat_updates.enemy: "none"` / `"Unknown Enemy"`; the combat-fidelity code instantiated a **hostile NPC literally named "none"** that then persisted in `active_npcs`. Placeholder enemy names must be rejected.
- **Combat has no stakes:** `player_updates.hp_change` was 0 every turn; fights resolve narratively with no mechanical damage.
- **Travel not reflected in UI (#3):** narration-only "I travel there" does not move the character (movement is `current_location_id`-driven). The UI travel/map control isn't sending/reflecting the change — top bar + env pane stay on the old location and the old NPC stays "stuck". Frontend bug.
- **NPC pile-up (#4):** every "talk to someone" spawned a new NPC at the same location (5+ accumulated), none in earshot — scene clutter.
- **UI-layer reports unverified by API but consistent with the build:** #2 audio flicker, #6 inert Show Dialogue, #7 empty Journal, #8 no bounty view / multiple quest-like entries, #9 guild refresh, #10 world-tick phantom NPCs, #11 combat pane/chat lockout.

See `ROADMAP.md` for the chunked, saosgo-ready fix backlog derived from the above.
