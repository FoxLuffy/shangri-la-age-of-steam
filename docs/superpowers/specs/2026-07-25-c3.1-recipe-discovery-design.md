# C3.1 — Recipe Discovery System Design

Roadmap item: **C3.1** (Crafting Depth). Backend only — the CraftingPanel UI is C3.3.

## Goal
Recipes are not known by default. Each character discovers recipes and can only craft
what they've discovered. Discovery happens through a generic grant (used by the
dialogue / exploration / purchase paths) plus a first-class **experimentation** mechanic.

## Decisions (confirmed)
- Scope = data model + generic discover + full experimentation + gate `/craft`.
- Gate crafting: crafting an undiscovered recipe returns **403**.
- **Zero starter recipes**: new characters know nothing; everything is discovered.
- The 3 non-experiment paths are represented by the generic `POST /crafting/discover`
  (auto-triggers wired to NPC disposition / exploration / Workshop later).

## Model (`backend/database.py`)
```python
class KnownRecipe(SQLModel, table=True):
    __tablename__ = "known_recipe"
    __table_args__ = (UniqueConstraint("character_id", "recipe_id"),)
    id: Optional[int] = primary key
    character_id: int = FK character.id, index
    recipe_id: int = FK recipe.id, index
    method: str = "discovery"          # dialogue | exploration | experimentation | purchase
    discovered_at: str = ""
```
+ Alembic migration for `known_recipe`.

## Router (`backend/routers/crafting.py`, registered in `main.py`)
- `GET /crafting/known?character_id=` → `[{recipe_id, name, method, discovered_at}]`.
- `POST /crafting/discover {character_id, recipe_id, method="discovery"}`:
  - 404 if character or recipe missing.
  - Idempotent: if already known, return `{status:"already_known"}`; else create the row
    and return `{status:"discovered", recipe_id}`.
- `POST /crafting/experiment {character_id, item_ids:[int]}`:
  - Candidate recipes = those whose every `RecipeRequirement.item_id` is in `item_ids`,
    excluding recipes the character already knows.
  - If no candidate → `{discovered: null}`.
  - Else roll `random.random() < DISCOVERY_CHANCE` (module constant, default 0.5). On
    success, discover one candidate (method="experimentation") and return it; else
    `{discovered: null}`.

## Gate (`backend/main.py` `/craft`)
After loading the recipe, require a `KnownRecipe` for `(character_id, recipe_id)`; else
raise **403** ("You have not discovered this recipe"). (Live `/craft` is in `main.py`;
the `economy.py` copy is not registered.)

## Tests
- `backend/tests/test_crafting_discovery.py`:
  1. discover creates a KnownRecipe row; second call is idempotent (no duplicate).
  2. discover with unknown character → 404; unknown recipe → 404.
  3. `GET /crafting/known` lists discovered recipes with name + method.
  4. experiment with a matching recipe + forced success (monkeypatch `random.random`)
     → discovers it (row + payload); already-known recipes are excluded.
  5. experiment with non-matching materials → `{discovered: null}`, no row.
  6. craft gate: crafting an undiscovered recipe → 403; after `/crafting/discover`
     the same craft → 200.
- Update `backend/tests/test_faction_crafting.py`: call `/crafting/discover` before the
  first `/craft`.

## Out of scope
- Auto-triggers for dialogue/exploration/purchase, specialization trees (C3.2),
  CraftingPanel UI (C3.3), success-rate/proficiency effects.

## Acceptance
- Undiscovered recipes cannot be crafted (403); discovery unlocks crafting.
- Experimentation can discover a recipe from held materials.
- Full suites green plus new tests; `ruff` clean.
