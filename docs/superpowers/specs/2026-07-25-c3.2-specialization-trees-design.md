# C3.2 — Crafting Specialization Trees Design

Roadmap item: **C3.2** (Crafting Depth). Depends on C3.1 (discovery gate on `/craft`).
Backend only — CraftingPanel UI is C3.3.

## Goal
Three crafting branches — **Metallurgy, Alchemy, Clockwork** — each with a per-character
proficiency level 0–10. Proficiency gates higher-tier recipes and improves success rates;
it grows by successful crafting.

## Decisions (confirmed)
- Proficiency stored in a `CraftingProficiency` table (one row per character+branch).
- Crafting can **fail**; failure consumes materials; proficiency raises the odds.
- Successful crafts grant XP; `tier` gates crafting (blocked with 400).

## Model (`backend/database.py`)
- `Recipe` gains:
  - `branch: Optional[str] = None`  # "metallurgy" | "alchemy" | "clockwork"
  - `tier: int = 0`                 # min proficiency level required
- New table:
  ```python
  class CraftingProficiency(SQLModel, table=True):
      __tablename__ = "crafting_proficiency"
      __table_args__ = (UniqueConstraint("character_id", "branch"),)
      id, character_id (FK, idx), branch, xp: int = 0
  ```
- Alembic migration: two `recipe` columns + the new table.

## Constants & helpers (`backend/routers/crafting.py`)
```python
BRANCHES = ["metallurgy", "alchemy", "clockwork"]
XP_PER_LEVEL = 3
MAX_LEVEL = 10
SUCCESS_BASE = 0.5
SUCCESS_PER_LEVEL = 0.1

def level_for_xp(xp) -> int:            # min(MAX_LEVEL, xp // XP_PER_LEVEL)
def craft_success_chance(level, tier):  # clamp(SUCCESS_BASE + SUCCESS_PER_LEVEL*(level-tier), 0.05, 0.98)
def roll_success(chance) -> bool:       # random.random() < chance  (monkeypatch point)
def get_or_create_proficiency(session, character_id, branch) -> CraftingProficiency
def add_craft_xp(session, character_id, branch) -> None   # xp += 1
```

## `/craft` changes (`backend/main.py`, after the C3.1 discovery gate)
- `recipe.branch is None` → unchanged: no tier gate, deterministic success, no XP
  (keeps existing craft tests + basic recipes working).
- `recipe.branch` set:
  1. `level = level_for_xp(proficiency.xp)`; if `level < recipe.tier` → 400
     ("Requires {branch} proficiency {tier}").
  2. Deduct materials (as today).
  3. `chance = craft_success_chance(level, recipe.tier)`; if `roll_success` fails →
     commit the material loss and return `{"crafted": false, "status": "failed", ...}`.
  4. On success → add result item, `add_craft_xp`, return the existing success payload
     plus `"crafted": true`.

## Endpoint
`GET /crafting/proficiency?character_id=` → `[{branch, level, xp}]` for all three
branches (auto-initialised to 0 if absent).

## Tests (`backend/tests/test_crafting_specialization.py`)
1. `GET /crafting/proficiency` returns all 3 branches at level 0.
2. Branched recipe with `tier` above the character's level → craft 400.
3. Meeting the tier + forced success (monkeypatch `roll_success`/`random`) → craft 200,
   `crafted: true`, XP incremented (proficiency endpoint reflects it).
4. Forced failure → 200 `crafted: false`, materials consumed, no result item, no XP.
5. `level_for_xp` caps at 10 (pure-function unit test).
6. Non-branch recipe → deterministic success, no XP (regression).

## Out of scope
- CraftingPanel UI (C3.3), branch-specific bonuses beyond success rate, recipe seeding.

## Acceptance
- Higher-tier branched recipes are blocked until proficiency is high enough.
- Branched crafts can fail (materials lost) with proficiency-scaled odds; success grants XP.
- Non-branch recipes behave exactly as before.
- Full suites green plus new tests; `ruff` clean.
