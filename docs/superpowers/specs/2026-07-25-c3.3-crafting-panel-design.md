# C3.3 — CraftingPanel UI Design

Roadmap item: **C3.3** (Crafting Depth). Depends on C3.1 (discovery) + C3.2 (proficiency).

## Goal
An in-game CraftingPanel: browse known recipes with requirements and success chance,
craft them, see branch proficiency, and experiment with materials to discover recipes.

## Decisions (confirmed)
- **Click-to-select** material grid (not real drag-and-drop).
- Success probability = the C3.2 formula (proficiency vs tier); no materials-quality /
  facility factors (those systems don't exist).
- Panel includes: recipe browser + craft + proficiency bars + experimentation.

## Backend (supporting reads, `backend/routers/crafting.py`)
- Enrich `GET /crafting/known` items with (existing keys retained):
  `branch`, `tier`, `result_item_id`, `result_name`,
  `requirements: [{item_id, name, quantity}]`.
- New `GET /crafting/materials?character_id=` → the character's owned items:
  `[{item_id, name, quantity}]`.
- Reuse `GET /crafting/proficiency`, `POST /craft`, `POST /crafting/experiment`.

## Frontend
- `api.ts`: `KnownRecipe`/`CraftingMaterial`/`Proficiency` types +
  `getKnownRecipes`, `getCraftingMaterials`, `getProficiency`, `craftItem`,
  `experimentCraft`.
- `CraftingPanel.tsx` — modal (AugmentationPanel/MarketUI pattern), props
  `{ characterId, onClose }`. Loads known recipes, materials, proficiency on mount.
  Sections:
  1. **Proficiency**: 3 branch bars (level/10, xp label).
  2. **Recipe browser**: each known recipe → name, `branch · tier` badge, requirements
     (`name ×qty`, greyed/red if the player lacks enough), **success %**
     (`successPct(level, tier)` mirroring `clamp(0.5+0.1*(level-tier),0.05,0.98)`;
     branchless recipes = 100%), a **Craft** button (disabled when materials are short)
     → shows a short progress bar → success/"failed" message → refetch all.
  3. **Experiment**: click-select grid of owned materials; **Attempt** calls
     `experimentCraft(characterId, selectedIds)`; shows the discovered recipe name or
     "nothing discovered"; refetch known recipes on discovery.
- Wire: `StatsPanel` gains `onOpenCrafting`; `App` adds `showCrafting` + renders
  `<CraftingPanel characterId onClose />`.

## Success-% helper (frontend)
```ts
export function craftSuccessPct(level: number, tier: number, branch: string | null): number {
  if (!branch) return 100;
  const c = Math.max(0.05, Math.min(0.98, 0.5 + 0.1 * (level - tier)));
  return Math.round(c * 100);
}
```

## Tests
- Backend (`test_crafting_discovery.py` additions):
  - `GET /crafting/known` includes `branch`, `tier`, `result_name`, and `requirements`
    with item names.
  - `GET /crafting/materials` returns owned items with names + quantities.
- Frontend (`CraftingPanel.test.tsx`, mocked api):
  - renders proficiency branch bars,
  - renders a known recipe with its name and a success % ,
  - clicking Craft calls `craftItem` then refetches known recipes,
  - selecting a material + Attempt calls `experimentCraft`,
  - close button calls `onClose`.

## Out of scope
- Real drag-and-drop, materials-quality/facility mechanics, crafting queue/batch.

## Acceptance
- Panel lists known recipes with requirements + success %, crafts them, shows proficiency,
  and can experiment to discover recipes.
- Full suites green plus new tests; `ruff` / `tsc` / `oxlint` clean.
