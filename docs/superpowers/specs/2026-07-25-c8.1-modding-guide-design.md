# C8.1 — Mod SDK Documentation Design

Roadmap item: **C8.1** (Expanded Modding Ecosystem). Documentation + a guarded template.

## Goal
A modding guide covering the JSON mod schema, supported entity types, upload mechanism,
upsert/validation behavior, and a runnable annotated template.

## Decisions (confirmed)
- Document the **actually supported** entities — factions, locations, npcs, items — with a
  short "Planned (not yet loadable)" note for recipes/bounties. No misleading schema.
- Ship a runnable `docs/mods/example_mod.json` **plus** a test that uploads it, so the
  template can't rot.

## Deliverables
- `docs/modding_guide.md` — upload (Settings UI + `POST /modding/upload` curl), file shape
  `{factions, locations, npcs, items}`, apply order, upsert table (faction/location/npc by
  `id`, item by `name`), per-entity field tables (sourced from the models), the
  `ItemCategory` enum, an annotated jsonc example, current validation rules, and the
  Planned/roadmap-pointer section.
- `docs/mods/example_mod.json` — valid mod with all four entity types (mod_-prefixed IDs).
- `backend/tests/test_modding_example.py` — loads the example, `POST /modding/upload`,
  asserts the faction/location/npc/item exist and key fields match.

## Source of truth
Field tables mirror `backend/database.py` models (`Faction`, `Location`, `NPC`, `Item`,
`ItemCategory`) and the real `/modding/upload` handler in `backend/main.py`.

## Out of scope
- Actual validation/sandboxing (C8.2), ratings (C8.3), dependencies (C8.4), making
  recipes/bounties moddable.

## Acceptance
- Guide accurately documents the 4 supported types + upload + upsert + validation.
- The example template uploads successfully (guarded by a test).
- Full suite green; `ruff` clean.
