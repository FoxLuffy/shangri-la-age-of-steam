# C8.3 — Mod Rating & Curation Design

Roadmap item: **C8.3** (Expanded Modding Ecosystem). Depends on the existing workshop
(registry.json + `/workshop/mods` + install).

## Goal
Let players rate installed mods (1–5 stars + optional review), surface aggregate ratings in
the browser, sort by rating/downloads, and highlight featured mods in a carousel.

## Decisions (confirmed)
- Ratings keyed by `user_id`; one per (mod, user) — re-rating **upserts**. Any listed mod
  can be rated (per-user installs aren't tracked; noted in the guide).
- **Featured** = average ≥ 4.5 with ≥ 1 rating, OR a registry `featured: true` flag.
- Sorting is **client-side** (Rating / Downloads); the backend returns aggregates and a
  featured flag; the browser renders a featured carousel.

## Model (`backend/database.py`)
```python
class ModRating(SQLModel, table=True):
    __tablename__ = "mod_rating"
    __table_args__ = (UniqueConstraint("mod_id", "user_id"),)
    id, mod_id: str (idx), user_id: int (idx), stars: int, review: Optional[str], created_at: str
```
+ Alembic migration.

## Backend (`backend/main.py`, workshop section)
Constants: `FEATURED_MIN_AVG = 4.5`, `FEATURED_MIN_COUNT = 1`.

- `POST /workshop/mods/{mod_id}/rate` body `{user_id, stars, review?}`:
  - `stars` outside 1–5 → 400.
  - upsert the (mod_id, user_id) row; return `{mod_id, avg_rating, rating_count}`.
- `GET /workshop/mods` (enriched): for each registry entry add
  `avg_rating` (rounded 2, 0.0 if none), `rating_count`, and
  `featured = registry.featured OR (avg_rating >= 4.5 and rating_count >= 1)`.
  Existing fields (id, name, description, author, downloads) retained.
- `GET /workshop/mods/{mod_id}/ratings` → `[{user_id, stars, review, created_at}]`.

Helper `_mod_rating_summary(session, mod_id) -> (avg, count)`.

## Frontend
- `api.ts`: `WorkshopMod` type (enriched), `rateMod(modId, userId, stars, review?)`,
  `fetchModRatings(modId)`. `fetchWorkshopMods` return type updated.
- `WorkshopBrowser.tsx` (`{ userId?: number | null }`):
  - **Sort** control: Rating (default) / Downloads.
  - **Featured carousel**: mods with `featured` shown in a highlighted horizontal strip.
  - Each card: name/author/description, ★ avg + count, downloads, **Install**, and a
    rating widget (1–5 star buttons + optional review textarea + Submit → `rateMod` →
    reload). Rating disabled when `userId` is absent.
- `App.tsx`: pass `userId` to `<WorkshopBrowser>`.

## Tests
- Backend (`backend/tests/test_mod_ratings.py`):
  1. rate a mod → `GET /workshop/mods` shows `avg_rating` + `rating_count`.
  2. same user re-rates → count stays 1, avg reflects the new value (upsert).
  3. `stars` = 0 or 6 → 400.
  4. a single 5★ rating makes the mod `featured: true`.
  5. `GET /workshop/mods/{id}/ratings` lists the review.
- Frontend (`WorkshopBrowser.test.tsx`, mocked api):
  - renders a mod with its star average + downloads,
  - featured mod appears in the featured section,
  - clicking a star + Submit calls `rateMod`,
  - Install still calls `installWorkshopMod`.

## Out of scope
- Tracking per-user installs, dependency chains (C8.4), moderation of reviews.

## Acceptance
- Players can rate mods; averages/counts show; sorting + featured carousel work; valid
  rating updates aggregates. Full suites green; `ruff` / `tsc` / `oxlint` clean.
