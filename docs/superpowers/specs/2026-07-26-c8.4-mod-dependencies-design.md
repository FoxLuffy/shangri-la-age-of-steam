# C8.4 — Mod Chains & Dependencies Design

Roadmap item: **C8.4** (Expanded Modding Ecosystem). Depends on the workshop
(registry.json + install) and C8.1/C8.2/C8.3.

## Goal
Mods can declare dependencies on other mods. Installing a mod auto-installs its
dependencies first, and warns (rather than aborting) when a dependency is missing.

## Decisions (confirmed)
- Dependencies declared in the **registry** entry: `dependencies: ["mod_id", ...]`.
- Missing dependency → still install the target, but return a **warning**.
- Fix the malformed sample mod files + wrap each mod's apply in try/except so one bad
  mod becomes a warning instead of a 500.
- Frontend: show a "Requires: …" line and an install summary (installed + warnings).

## Data
- `backend/workshop_mods/registry.json`: add `dependencies` to entries; `mod_2` depends
  on `mod_1`.
- Repair `mod_1.json` / `mod_2.json` to valid entities (string ids, real model fields).

## Backend (`backend/main.py`)
- `resolve_install_order(registry, mod_id) -> {"order": [...], "missing": [...], "cycle": bool}`
  — pure function. Builds an id→deps map, depth-first with deps before dependents,
  detects cycles (temporary marks), and records dep ids absent from the registry as
  `missing`. `order` ends with `mod_id` and contains only registry-present ids.
- `apply_mod_data(session, data)` — shared helper that upserts factions/locations/npcs/items
  (extracted from the existing install/upload logic).
- `POST /workshop/mods/{mod_id}/install`:
  - target not in registry → 404.
  - `cycle` → 400 ("dependency cycle").
  - else for each id in `order`: if `{id}.json` missing → warning; else apply via
    `apply_mod_data` in try/except (failure → warning); successes → `installed`.
  - missing deps → warnings.
  - returns `{"installed": [...], "warnings": [...]}`.
- `GET /workshop/mods/{mod_id}/dependencies` → the resolver result (404 if not in registry).
- `GET /workshop/mods` already returns registry entries, so `dependencies` passes through.

## Frontend
- `api.ts`: `WorkshopMod` gains `dependencies?: string[]`. `installWorkshopMod` result now
  `{installed, warnings}`.
- `WorkshopBrowser`: show `Requires: a, b` on cards that have dependencies; after install,
  show a summary message (`Installed: … | Warnings: …`).

## Tests
- Backend (`backend/tests/test_mod_dependencies.py`):
  - `resolve_install_order`: dependency ordered before dependent; `missing` lists absent
    deps; a cycle sets `cycle: true`.
  - `GET /workshop/mods/{id}/dependencies` returns the order for `mod_2` as `[mod_1, mod_2]`.
  - `POST /workshop/mods/mod_2/install` → `installed` contains `mod_1` before `mod_2`.
  - install with a synthetic missing dep → a warning naming it (via a temp registry, or a
    mod whose dep isn't present).
- Frontend (`WorkshopBrowser.test.tsx` addition): a mod with `dependencies` shows a
  "Requires" line.

## Out of scope
- Version constraints / semver, uninstall, transitive conflict resolution beyond cycle
  detection.

## Acceptance
- Installing a mod installs its dependencies first; missing deps/broken mods produce
  warnings, not crashes; cycles are rejected. Suites green; `ruff`/`tsc`/`oxlint` clean.
